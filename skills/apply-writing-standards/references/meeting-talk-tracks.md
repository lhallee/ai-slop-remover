# Meeting talk tracks

Use this profile for spoken technical explanations, slide narration, internal debate, objection handling, and live claim cleanup.

## Explanation pattern

1. Start with the concrete object.
2. Describe the input.
3. Name the transformation or model layer only as specifically as needed.
4. Describe the output.
5. State what the output means and does not mean.
6. End with the clean sentence the audience can reuse.

Keep the language speakable, direct, and lightly iterative. Use self-correction only when it clarifies the reasoning. Do not turn the talk track into a blog paragraph or polished sales script.

## Pushback pattern

1. Identify the risky word or implication.
2. Explain why it is unsupported or misleading.
3. Replace it with a narrower phrase.
4. State what the evidence permits.

Separate architecture from the feature that creates an observed advantage. Treat scores as decisions or priorities rather than experimental truth unless validation supports the stronger claim.
