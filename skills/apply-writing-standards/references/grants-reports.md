# Grants and reports

Use this profile for proposals, letters of intent, progress reports, final reports, impact statements, milestone summaries, and funder responses.

## Proposal

1. State the community or user bottleneck.
2. Explain what current tools or workflows leave unresolved.
3. Define the capability, dataset, infrastructure, or experiment that will exist.
4. Give preliminary evidence and existing adoption where relevant.
5. Name deliverables, validation, controls, resources, and timing.
6. State the practical scientific or public value.

Make compute, storage, staffing, sample counts, controls, and timelines arithmetically consistent. Distinguish the reusable product from the reference run used to validate it. Use future tense for deliverables and present or past tense only for existing work.

## Progress or final report

1. State the original goal.
2. Explain any pivot and the evidence that justified it.
3. Report concrete outputs and measured results.
4. List products only when the reporting form requires it.
5. Explain practical impact without repeating the result.
6. State the specific funding or resource counterfactual.

Do not apologize for an evidence-based pivot or pretend it was the original plan. If a form repeats similar questions, adapt the same evidence to the requested purpose instead of pasting the same paragraph.

## Funder or reviewer response

Map each concern to:

1. the concern;
2. the response;
3. the exact change;
4. any remaining limitation.

Reconcile counts, thresholds, compute, controls, release timing, and scope explicitly. Be direct and non-defensive.

## Claims

- Do not claim broad community impact from an internal prototype.
- Make openness concrete through licenses, interfaces, data, tests, documentation, release venues, or reproducibility artifacts.
- Tie public value to access, cost, reuse, reproducibility, or a specific scientific capability.
- Label preliminary results and connect them to the validation plan.
